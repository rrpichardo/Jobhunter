# M0 source and extraction contract implementation plan

**Spec:** `docs/PLAN.md` M0 and V0 source/identity rules;
`docs/IMPLEMENTATION_PROMPT.md` steps 2–3. Existing design and execution are
user-authorized. This is the first M0 code PR, not completion of M0.

**Goal:** Fetch a single configured Greenhouse board in Python, retain source
evidence, accept a narrowly bounded Claude excerpt contract, and derive normalized
Sheet-ready records in Python. Do not write any Sheet cells in this PR.

**Architecture:** Plain Python modules at `jobhunter/`; module entry points at
`scripts/`. One owner implements; lower-cost helpers only research independent
cloud prerequisites. Tests use synthetic public-job data and httpx MockTransport.
Production model calls remain Claude subscription tool use, not paid API calls.

## Tasks and interfaces

1. `jobhunter/records.py`: frozen `SourceJob` plus `validate_extractions(jobs,
   payload)` produces dictionaries keyed by the plan's Jobs headers. Python derives
   `greenhouse:<board>:<public-job-id>`; Claude supplies only `job_id` and a
   verbatim `description_quote` from the provided source text. Reject unknown IDs,
   duplicate extractions, unknown keys, wrong types, and unsupported quotations.
   This is source normalization, not full eligibility or a fit score.
2. `jobhunter/fetch.py`: `JsonFetcher.get_json(url)` uses explicit timeout,
   at most three total attempts, bounded backoff, and Retry-After (seconds/date).
   Stop if server's requested wait exceeds the configured wait budget; never
   shorten it and retry early. Only transient failures are retried; no social
   collector uses this generic retry path.
3. `jobhunter/greenhouse.py`: `collect_board(fetcher, board, company,
   ai_company, captured_at)` produces typed jobs and a source result. Validate
   public IDs and URLs. Malformed/failed is distinct from a valid empty board.
   No source failure becomes a claim that jobs closed.
4. `scripts/v0_harvest.py`: fetch the one M0 registry route and write JSON outside
   the repo to an operator-selected protected work directory. Include source
   status, counts, complete-response coverage and capture time. Default limit is
   one PM candidate for M0 extraction; metadata exposes sampled coverage.
5. `scripts/validate_extractions.py`: validate Claude's JSON against saved source
   jobs and emit normalized records for the upcoming Python writer. The CLI
   rejects malformed inputs with a sanitized reason and checks the trusted harvest
   SHA-256 reference; no credentials or mail read. Zero/partial extraction returns
   nonzero with explicit selected/validated counts, not successful delivery.
6. `docs/M0_EXTRACTION_PROMPT.md`: exact cloud extraction steps and untrusted-source
   rules. JSON evidence is a proposed fact, never an instruction or cell update.

  Claude cloud session. Record that as manual cloud evidence only. M0 remains
